把博客搬上 GitHub Pages，顺便记一下踩的坑

2026 · 10 · 22 · 部署 · 约 4 分钟

想有个写东西的地方，要求很低：不用买服务器，不用配数据库，打开就能看，改完推上去就生效。GitHub Pages 正好是干这个的。

它到底是什么

简单说：你在仓库里放一堆静态文件（HTML / CSS / JS / 图片），GitHub 拿一台机器帮你挂出去，给你一个域名。没有任何后端，没有 PHP，没有 Node 进程在跑。

这对博客来说完全够了。博客的绝大部分内容，本来就是"编译完就不变"的东西。

项目页的地址长这样：

https://<用户名>.github.io/<仓库名>/

如果你把仓库直接命名为 <用户名>.github.io，地址就会变成 https://<用户名>.github.io/，不带子路径。

坑一：绝对路径会全挂

这是最容易踩的一个。项目页部署在 /blog/ 这样的子路径下，所以你在本地写 <link href="/assets/style.css">，本地双击打开时是好的（因为根目录就是文件所在盘），推上去就变成了 https://<用户名>.github.io/assets/style.css——那个文件根本不存在。

解决办法很土但很有效：全部用相对路径。

<!-- 首页 -->
<link rel="stylesheet" href="assets/style.css">

<!-- 子目录里的页面 -->
<link rel="stylesheet" href="../assets/style.css">

代价是你不能把页面挪来挪去而不改路径，但换来的是它在任何子目录下都能跑，连本地直接双击也能正常显示。对一个小站来说，这笔买卖划算。

坑二：下划线开头的文件会被吃掉

GitHub Pages 默认跑 Jekyll。Jekyll 会把以 _ 开头的目录（比如 _sass、_layouts）当成自己的东西处理，不当作静态文件发布。

如果你完全不用 Jekyll，就在仓库根目录放一个空的 .nojekyll 文件。这样 GitHub 会原样发布所有文件，也省掉一次构建，推送后生效更快。

touch .nojekyll

坑三：认证，不是写好文件就能推

2021 年之后 GitHub 不再接受账号密码推送，只能用 Personal Access Token 或者 SSH key。第一次 git push 会卡在那里要密码，输账号密码是没用的。

我目前的办法是生成一个 classic token（勾 repo 权限），在本机配置好凭据存储，之后就不用再管了：

git config --global credential.helper manager
git remote set-url origin https://github.com/xiray/blog.git
# 第一次 push 时用 token 当作密码

顺便说一句，如果你的机器走代理，git 默认不会用系统的代理变量，得单独告诉它：

git config --global http.proxy http://127.0.0.1:端口

不然就是一直卡住，没有报错，没有提示，什么都不发生——比报错还难受。

坑四：别指望它快

GitHub Pages 的服务器在国外，国内访问速度看运气。静态资源还好，几 KB 的 HTML 加载不慢，但第一次解析域名可能要一两秒。真要快，得上 CDN 或者换托管，但那就不是"不花钱不折腾"了。

所以这个站做得很轻：没有框架，没有 CDN，没有字体文件，没有一个外部请求。整站加起来不到 100 KB，图片一个都没有。

值不值得

值得。写一篇文章的成本就是新建一个 HTML 文件，Ctrl+C、Ctrl+V 改一改，加一条列表，git push。没有构建步骤意味着没有构建失败，三年后回来它还在。

工具应该比它服务的东西活得更久。静态文件大概是目前最接近这个目标的东西。
